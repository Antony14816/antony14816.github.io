### システム構成

**構成の説明文（この欄に貼り付け）**

Mashup Oursは、ProtoPedia APIで取得した作品情報を使い、GitHub Pages／Issues／Actionsを組み合わせて配合を行う構成です。認証付きAPI通信と生成AIの実行はGitHub Actionsに集約し、公開サイトには取得・整形済みのデータと配合結果のみを表示します。配合申請はGitHub Issuesで受け付け、1時間に最大1件を処理する設計です。

```text
ProtoPedia API v2
       │ 作品情報取得（Bearer Token）
       ▼
GitHub Actions ──> 公開用作品JSON ──> GitHub Pages
                                         │
                                   親作品A/Bを選択
                                         │
                                         ▼
                                  GitHub Issues
                                    （配合申請）
                                         │
                                         ▼
                                   GitHub Actions
                                    （毎時最大1件）
                                         │
                                         ▼
                                      生成AI
                                         │
                                         ▼
                              配合結果・系譜JSON
                                         │
                                         ▼
                                  GitHub Pages
                                  （結果・系譜図）
```

**使用技術と役割**

| 技術・サービス | 役割 |
| --- | --- |
| ProtoPedia API v2 | 作品名・概要・技術情報・原作品リンクなどの取得 |
| GitHub Pages | 静的Webサイト、作品選択、結果・系譜図の表示 |
| GitHub Issues | 2作品のIDを含む配合リクエストを受け付ける |
| GitHub Actions | 取得・同期、配合申請の検証、定期実行 |
| 生成AI API | 2作品の特徴を抽出し新しい発明案を生成 |
| JSON / GitHubリポジトリ | 配合結果、親子関係、生成履歴の保存 |
| TypeScript等 | Web UIとActions処理の実装（実装時に確定） |

※使用する生成AIモデル、実装言語の細部、デプロイ状況は公開時に確定してください。GitHub Actionsの定時実行には遅延・スキップの可能性があり、毎時ちょうどの生成は保証しません。

### 開発背景・ストーリー（本文欄に貼り付け）

# Mashup Ours — 20年分の発明を、もう一度マッシュアップ。

**誰かの発明と、別の誰かの発明が出会ったら、何が生まれるだろう？**

ProtoPediaの作品を「親」にして、生成AIと一緒に次の発明を生み出す、ちょっと怪しい発明配合研究所。それが **Mashup Ours（マッシュアップアワーズ）** です。

## Mashup AwardsからMashup Oursへ

ヒーローズ・リーグの前身は「Mashup Awards」。もともとAPIやサービスを組み合わせ、新しい作品を生み出すマッシュアップの文化がありました。

そして今、ProtoPediaには、長い時間をかけて作り手たちが積み重ねたユニークな発明が並んでいます。

**API同士を組み合わせるのではなく、登録された「発明そのもの」をマッシュアップしたら？**

これが企画の出発点です。

名前は **Mashup Awards** へのオマージュであり、**Ours＝「私たちのもの」** という意味も込めています。「誰かの発明が、みんなの次の発明のきっかけになる」という願いです。

## どうやって遊ぶ？

1. **親を選ぶ。** ProtoPediaに登録された2つの作品を選択。
2. **配合を申し込む。** GitHub Issuesに作品IDを添えて申請。
3. **研究所が配合する。** GitHub Actionsが順番に処理し、生成AIで新しい発明案を考える。
4. **子作品が誕生する。** 新しい名前、概要、技術構成、親から受け継いだ特徴を記録。
5. **系譜図を育てる。** 生まれた作品をさらに別の発明と配合し、世代をつないでいく。

※上記は目指している体験の全体像です。公開時点の実装状況に応じ、未実装機能は「開発中」と表示します。

## こだわり① 「生成」より「配合」

生成AIに「面白いアイデアを考えて」と頼むだけでは、どこかで見た案になりがちです。Mashup Oursでは、**実在する2作品の特徴を出発点にする**ことを重視しています。

- **技術の遺伝子**：使ったAPI、デバイス、入出力、実装の工夫
- **体験の遺伝子**：誰が、どんな場面で、どう楽しむか
- **課題の遺伝子**：何を解決したかったのか
- **遊びの遺伝子**：役に立つか分からないけれど、なぜか惹かれる部分

例えば、Aの「動きを検出して光るIoT装置」とBの「地域の歴史を案内する散歩アプリ」を配合したら、「歴史上の事件が起きた場所で光り方が変わる歴史散歩デバイス」が生まれるかもしれません。

※この組み合わせは仕組みを説明するための架空例です。実在作品の生成結果ではありません。

大切なのは、**どちらの親から何を受け継いだか説明できること**。結果画面には、原作品の作者名・作品名・リンクを残す設計です。

## こだわり② 1時間に世界でひとつの発明

生成AIの無料枠での継続運用を目指し、**サービス全体で1時間あたり最大1件の配合**を行う設計にしています。

一人につき1回ではなく、研究所全体で1枠。申請を並べて順番を待ち、誕生した発明はみんなで閲覧できます。結果をJSONとして保存して、同じ結果を表示するたびにAIを呼ばないようにします。

コスト制限を、**「1時間に世界でひとつ、新しい発明が生まれる」** という体験に変えるのが狙いです。

※無料枠内での運用可否はモデル・トークン使用量・提供条件に依存します。

## こだわり③ 発明の系譜図

作品AとBからCが生まれ、CとDからEが生まれる。そんな**発明の系譜**を可視化したいと考えています。

```text
ProtoPedia作品 A ─┐
                  ├─ 子作品 C ─┐
ProtoPedia作品 B ─┘            ├─ 孫作品 E
                  別の作品 D ─┘
```

発明の関係は、単なる一覧ではなく、親と子をたどれるグラフとして記録する方針です。いつか「何世代も受け継がれたアイデア」「たくさんの子孫を残した作品」なども眺められるようにしたいです。

## こだわり④ GitHub自体が研究所

できるだけ専用サーバーを用意せず、GitHubの機能を組み合わせます。

- **Issuesは配合申請書**
- **Actionsは配合装置**
- **JSONは実験記録**
- **Pagesは発明の展示室**

GitHub Pagesから親作品を選んでIssue投稿画面へ移動し、Actionsが配合結果を保存する。GitHubの標準機能自体を作品の仕組みと見立てています。

## こだわり⑤ MOTHER2のような温かみのある研究所

AIサービスによくある、青紫のグラデーションや無機質なダッシュボードにはしたくありません。

目指しているのは、**レトロRPGの少しおかしな研究所**。16bitのピクセルアート、ゲーム風の会話ウィンドウ、怪しい配合マシン、変わり者のオリジナル博士がいる世界観です。

雰囲気の参考は『MOTHER2』の色使い・ユーモアと、初期『ポケットモンスター』のマサキの家のようなワクワクする実験空間。キャラクターや画面をコピーせず、オリジナルの研究所として表現します。

「作品を選ぶ」こと自体を、レトロゲームのアイテム図鑑を開くような体験にしたいと思っています。

## ProtoPedia APIを使う意味

ProtoPedia APIで作品の名前だけでなく、概要や技術情報も取得し、配合の材料に使う構成です。元作品のクレジットと原ページへのリンクを残し、**誰のどの発明が、新しいアイデアのきっかけになったか**分かるようにします。

既存には、AIから作品を検索できる [protopedia-mcp](https://protopedia.net/prototype/8454)、応募作品の傾向を分析する [HeroesLeague Analysis](https://protopedia.net/prototype/8496)、作品情報を可視化する [Chroco](https://protopedia.net/prototype/1393) などの活用例があります。

Mashup Oursが重視するのは、作品を**探す・分析する**だけでなく、作品同士から**新しい発明を生み出し、そのつながりを次世代へ残す**こと。既存作品の機能を完全に調査し尽くしたという意味ではなく、目指す体験の違いです。

## これから

まずは、親作品の選択、Issueによる配合申請、生成AIによる発明案の記録と表示を形にします。その後、子作品同士の配合、祖先をたどれる系譜図、配合方法の切り替えなどに育てていく構想です。

**Mashup Awardsから、Mashup Oursへ。**

誰かの「作ってみた」が、次の誰かの「作りたい」になる研究所を目指しています。
