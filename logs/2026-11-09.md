# 開発ログ 2026-11-09

## ProtoPedia API 実接続の確認（実トークンで取得）

- `GET https://protopedia.net/v2/api/prototype/list`（Bearer認証）の実レスポンス形状を確認:
  `{metadata, count, links, results}`。**`count` はページ内件数**（総数ではない）。
- カタログ件数外の offset は **HTTP 200 + `count:0` で `results` キー自体が無い**
  （= 最終ページの直後。エラーにせず空ページとして正常終了させる実装にした）。
- `users` / `tags` は `|`-区切りの**文字列**。作者は `表示名@handle` 形式
  （例の形式は `ひさやん@hisayan` / `@handle` のみのケースあり）→ **原文のまま保存**（クレジット表示用）。
- `licenseType: 1` → 作品ページ表示「CC BY 4+」（id=1 のページと照合済み）。
  取得時はライセンス情報を確認できた作品だけ保存する方針をコードに反映。
- カタログ総数は 5,100件超（正確な総数は未測定。プローブは途中でタイムアウト）。
- `data/sample-prototypes.json` に12件保存（全件ライセンスあり・画像URLあり・`freeComment` 全文は保存しない）。

## 候補ローテ（毎時6件）の実装

- `lib/candidates.ts`: スロット（UTC `YYYY-MM-DDTHH`）→ FNV-1aハッシュ → mulberry32 →
  数値IDソート後の Fisher-Yates で6件を**決定的に**選出。
  同じスロットなら常に同じ6件（Actionsの再実行・プール順序に依存しない）。単体テスト15件。
- `scripts/fetch-sample-prototypes.mjs`（少数取得のみ。**全件収集はまだ開始しない**、
  `--count=` 上限50 / `--offset=`）と `scripts/rotate-candidates.ts`
  （`--slot=` / `--dry-run`、JSONの `source` はリポジトリ相対パス、0件・不正データでも既存JSONは無変更）。
- `.github/workflows/rotate-candidates.yml`（毎時 cron + dispatch、`concurrency`、
  入力値はシェルへ直接埋めず `env` 経由、権限は `contents: write` のみ。APIトークンは使わない）。
- `sync-prototypes.yml` は **schedule を外して手動 dispatch のみ** に変更（試作段階では全件同期しない）。
- `data/current-candidates.json` 生成: `slot=2026-11-09T12` / 候補6件 / 次回 `2026-11-09T13`。

## 候補カードUI（画面完成イメージ準拠）

- ユーザー提供の完成イメージ（`tmp/` のスクリーンショット、リポジトリには含めない）に合わせ、
  **「本日の発明研究所 / LAB / INVENTION CANDIDATES」パネル** + 右上バッジ
  （本番「毎時6件・全ユーザー共通」/ 未同期「開発用サンプル」）+ 3列カードを実装。
  900pxで2列、560pxで1列。**自由検索（select・テキスト入力）は廃止**。
- カード = 画像タイル（`object-fit: contain` / `loading: lazy` / 失敗時は「画像なし」プレースホルダで枠維持、
  画像はドット化しない）+ `作品 No.NN` + 作品名 + 作者 + 概要2行 + ProtoPediaリンク +
  「Aにする」「Bにする」。タップ目標40px。
- 選択状態は **タイル枠色 + バッジ「親A選択中」+ `aria-pressed`** の三重化（色だけに依存しない）。
  A≠B・再クリックで解除・子作品の行（最近誕生した発明）からも親に指定できる。
- 交配マシンに 親A×親B のステータス行、現在の交配枠（UTC）、
  「1時間1枠は全ユーザー共有」、交配待ち公開Issueリンクを表示。
- Issue本文に **`slot`** と **`parent_a_url` / `parent_b_url`**（https のみ受理）を追加。
  URLは「データ」として扱い、ワーカーは親IDから出典URLを再導出する方針（信用しない）。
- サンプル注意書きを「候補が未同期」「子作品が0件」の2つに分離（実データなのに誤解される文言を修正）。
