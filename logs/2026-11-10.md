# 開発ログ 2026-11-10

## カスタムドメイン公開で画面が真っ黒になった件（baseパス不整合）

- DNSを `https://mashup-ours.suke.dev` に変更後、トップが真っ黒で表示されない（ユーザー報告・スクショ確認）。
- **原因**: カスタムドメインの project Pages は**ルート配信**（`/`）なのに、ビルドの base が
  `GITHUB_REPOSITORY` 由来の `/mashup-ours/` のままだった。
  - HTMLは `/mashup-ours/assets/main-*.js` と `/mashup-ours/assets/*.css` を参照 → **すべて404**
  - CSS/JSが1本も読めないため本文領域も描画されない（`/` は200、`/mashup-ours/` は404を実測で確認）。
- **修正**: `vite.config.ts` の base を既定 `/` に変更。`VITE_BASE=/<repo>/` を明示指定したときだけ
  パス付き公開（カスタムドメインなしの `<owner>.github.io/<repo>/` 向け）にできる優先順位のまま。
  Issue リンクの `GITHUB_REPOSITORY` 注入は対象外なので変更なし。
- 検証:
  - `npm run build` → `dist/index.html` / `dist/ideas/index.html` の参照が `/assets/...`（ルート絶対）になることを確認。
  - `npm test` → **126件合格**。
- README の Pages 設定手順を実態（カスタムドメイン・ルート配信・`VITE_BASE` の使い分け）に更新。
- **残課題**: push → `deploy.yml` の再デプロイ後、本番 `https://mashup-ours.suke.dev/` と `/ideas/` の
  アセット読込・`/data/offspring.json` 配信を再確認する（ローカルビルドでのパス検証のみ完了）。

## ドメイン変更に備えた相対base化

- ユーザー指示「ドメインは変わる可能性ある」→ 絶対パス base は**毎回のドメイン/公開パス変更でビルド設定が必要**になるため、**相対base（`./`）へ変更**。
  - `vite.config.ts`: `base` の既定を `'./'`。`VITE_BASE` の絶対パス上書きは維持。
  - 出力: `index.html` → `./assets/...`、`ideas/index.html` → `../assets/...`（Viteがページごとに解決）。
  - アプリ内URL:
    - `main.ts` は常にルートページ → `BASE_URL`（`./`）のまま `./ideas/`・`./data/offspring.json` ✓
    - `ideas.ts` は `<root>/ideas/` にいるため、相対base時はサイトルートへの基点を `'../'` に切り替え
      （トップリンク・`?id=` ディープリンク・フッター）。絶対base時はそのまま `BASE_URL`。
  - 動作確認: カスタムドメインルート / `<repo>` パス / フォーク / ローカル preview すべて同一ビルドで動作
    （相対解決のため）。`npm test` **126件合格**、`npm run build` 成功、
    previewで `/`・`/ideas/` ともスタイル適用をスクリーンショット確認（`../assets` が効いている）。
- README の Pages 設定手順を相対base前提に更新。
